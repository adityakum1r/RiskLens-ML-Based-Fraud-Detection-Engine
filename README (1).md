# Fraud Detection & Risk Scoring System

A machine learning pipeline that detects fraudulent transactions in the highly imbalanced PaySim dataset and converts model predictions into an easy-to-read 0–100 risk score.

## Overview

Fraud is rare, so accuracy alone is a misleading metric. This project focuses on:

- Handling severe class imbalance with class weights
- Evaluating with a realistic **time-based split** instead of a random one
- Tuning the decision threshold on validation data only
- Turning fraud probabilities into **Low / Medium / High** risk categories

## Approach

**Data preparation**
- Dropped missing values and exact duplicates
- Sorted by `step` and split chronologically: 70% train / 15% validation / 15% test

**Feature engineering**
- Time: hour of day, day, night-time flag
- Balances: sender and receiver balance changes, balance inconsistency
- Amount: log amount, amount relative to sender and receiver balance, zero-balance flags
- Transaction type (one-hot encoded)

**Models compared**
1. Logistic Regression
2. Random Forest
3. HistGradientBoosting

Random Forest was selected as the final model based on validation performance. Logistic Regression and Random Forest use `class_weight="balanced"`.

**Threshold selection**
The decision threshold was chosen on the validation set (max F1 on the precision-recall curve) and then applied once to the untouched test set. The final value used was **0.45**.

Final Random Forest model on the held-out test set:

| Metric | Score |
|---|---:|
| Precision | 100.00% |
| Recall | 99.95% |
| F1-Score | 99.98% |
| ROC-AUC | 100.00% |
| PR-AUC | 100.00% |

### Limitations

These near-perfect scores should **not** be read as real-world performance:

- PaySim is **synthetic**, and its fraud is generated by simple rules that are easy for tree models to learn.
- Several features (`newbalanceOrig`, `newbalanceDest`, `orig_balance_change`, `orig_error`) are computed from post-transaction balances. In PaySim these almost directly reveal fraudulent behaviour, and in a live system they would not be known at prediction time, which makes this a likely source of target leakage.
- Planned improvement: re-run the models using only information available before a transaction completes, and compare results.

## Risk Scoring

The fraud probability is multiplied by 100 to give a risk score.

| Score | Risk Level |
|---|---|
| 0–30 | Low Risk |
| 30–70 | Medium Risk |
| 70–100 | High Risk |

Example: a predicted probability of 0.85 gives a risk score of 85, which is **High Risk**.

## Dataset

[PaySim](https://www.kaggle.com/datasets/ealaxi/paysim1) is a synthetic mobile-money transaction dataset. Key columns:

- `step` – time unit (1 step = 1 hour)
- `type` – CASH-IN, CASH-OUT, DEBIT, PAYMENT, TRANSFER
- `amount`
- `oldbalanceOrg`, `newbalanceOrig`, `oldbalanceDest`, `newbalanceDest`
- `isFraud` – target label

The raw CSV is not included in this repository. Download it from Kaggle and place it in the project folder before running the notebooks.
